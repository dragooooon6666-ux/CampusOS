问题 3：组织层级结构

文件中心的归档结构应该如何设计？

方案 A：扁平列表（简单直接）

所有组织平铺，用户选一个归档。类似现在 FileOrganizer 的分类模式。

文件归档 — 选择归属组织
🏛️ 团委
📋 学生会
💼 就业服务部
🔬 科创部
🚩 党支部

方案 B：二级树形（部门 → 活动/项目）

每个组织下有子分类，文件归属更精确。结构更深但更有序。

文件归档 — 组织 → 项目层级
📁 团委
├─ 📂 2025五四评优
├─ 📂 2025团日活动
└─ 📂 2026春季推优
📁 学生会
├─ 📂 迎新晚会
├─ 📂 校园歌手大赛
└─ 📂 校企合作会议
📁 就业服务部
├─ 📂 春季招聘会
└─ 📂 企业宣讲会
A

扁平列表

简单够用，适合组织数量少、文件量不大的场景

B

二级树形

更接近真实组织结构，但需要更多配置和维护

C

B + 可自定义

二级树形基础上，允许用户在设置中添加/修改/删除组织和子项目
